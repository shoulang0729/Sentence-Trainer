# 07. 技術・プラットフォーム検討

> プラットフォームは**未確定**。本ページで選択肢を比較し、意思決定の材料を整理する。最終決定は別途記録する（`TBD`）。
>
> 前提: **個人用だが共有/学習状況シェアがある**ため、アカウントとバックエンド（同期）は必須。

## 7.1 プラットフォーム候補の比較

| 観点 | Webアプリ（PWA） | ネイティブモバイル | クロスプラットフォーム（React Native / Flutter） |
|------|------------------|--------------------|------------------------------------------------|
| 開発速度・初期コスト | ◎ 速い・低コスト | △ OSごとに開発 | ○ 1コードで2OS |
| インストール不要 | ◎ URLで即利用 | × ストア経由 | × ストア経由 |
| 中国語入力（IME） | ◎ OS標準IME利用 | ◎ | ◎ |
| 一括登録（ファイル/貼付） | ◎ デスクトップ併用が快適 | △ モバイルは貼付中心 | △ |
| オフライン学習 | ○ Service Worker | ◎ | ◎ |
| プッシュ通知 | △ 制約あり（特にiOS） | ◎ | ◎ |
| 発音録音/STT | ○ Web API（精度差） | ◎ ネイティブAPI | ○ プラグイン |
| 配布・更新 | ◎ 即時反映 | △ 審査 | △ 審査 |

### 推奨の考え方
- **一括登録やセンテンス管理はPC（Web）が快適**、一方で**日々の復習・通知はモバイルが有利**。
- 折衷案: **Web（PWA）でMVP** → 反応を見てモバイル化、または最初から**クロスプラットフォーム**で両取り。
- 共有がある以上、いずれの場合も**バックエンド＋同期**が前提。

> 決定に必要な追加インプット（`要検討`）: 主に使う端末（PC中心/スマホ中心）、通知・発音の優先度、開発リソース。

## 7.2 アーキテクチャ案（プラットフォーム非依存）

```
[クライアント (Web/モバイル)]
   - 登録UI / 学習UI / 演習ロジック / SRSスケジューラ
   - ローカルDB（オフライン: IndexedDB / SQLite 等）
        │  REST or GraphQL（HTTPS）
        ▼
[バックエンドAPI]
   - 認証 / 同期 / センテンス保存 / 共有・グループ / 統計集計
        │
        ▼
[データストア]  +  [オブジェクトストレージ（音声アセット）]
        +
[外部サービス]  TTS（音声生成）/ ピンイン変換 / STT（発音評価, 後続）
```

- **SRS計算の場所**は設計判断（`要検討`）: クライアント計算＋同期 / サーバ計算。
- **ピンイン自動生成**: ライブラリ（例: pypinyin 等）or API（`要検討`）。
- **音声(TTS)**: 中国語対応TTSで生成し、結果をキャッシュ（コスト最適化）。

## 7.3 技術スタック候補（たたき台）

> いずれも案。確定ではない（`要検討`）。

| レイヤ | 候補 |
|--------|------|
| フロント（Web） | React / Next.js, TypeScript, PWA |
| フロント（モバイル） | Flutter もしくは React Native |
| 状態/ローカルDB | IndexedDB（Web）/ SQLite（モバイル） |
| バックエンド | BaaS（Supabase / Firebase）または 自前（Node.js/Python） |
| データベース | PostgreSQL（リレーショナル、共有・統計に好相性） |
| 認証 | BaaS内蔵 or 自前（メール/ソーシャル） |
| 音声(TTS) | 中国語対応クラウドTTS（生成＋キャッシュ） |
| ピンイン変換 | ライブラリ or API |
| 発音評価(STT) | クラウドSTT（後続フェーズ、声調評価は `要検討`） |
| インフラ | マネージド（Vercel / Cloud Run / Fly.io 等） |
| 監視 | Sentry 等 |

### BaaS（Supabase/Firebase）採用の論点
- 利点: 認証・DB・同期・ストレージ・**共有/権限管理**が揃い、MVPを高速に作れる。共有機能との相性が良い。
- 注意: ベンダーロックイン、複雑な統計クエリの柔軟性。
- 共有・グループの**アクセス制御（行レベルセキュリティ等）** が要件上重要 → BaaSが有力候補。

## 7.4 外部依存とコスト
- TTS / STT / ピンイン変換 は従量課金になりうる。**生成結果のキャッシュ**で最適化。
- 発音の自動評価（声調含む）は精度・コストの難度が高いため、**自己評価/録音聞き返しから開始**し、段階導入（[08](08-ロードマップとMVP.md)）。
