# 09. 用語集

本プロジェクトで用いる用語の定義です。表記ゆれを防ぎ、認識を統一します。

> **はじめて読む方へ**：このドキュメントには技術用語も出てきます。本文中で意味の分からない言葉があったら、まずこのページを探してください。分野ごとに見出しで分けています。なるべく専門知識がなくても分かるように説明しています。

## 学習・トレーニングに関する用語

| 用語 | 定義 |
|------|------|
| 例文 / センテンス（Sentence） | 学習コンテンツの最小単位となる中国語の文。原文・日本語訳・ピンイン・重要単語などを持つ。ユーザーが自分で登録する。 |
| 重要単語（Keyword） | センテンス内で覚えたい主要な単語。トレーニング時に意味・解説をトグルで表示する対象。登録は任意。 |
| 個別登録 | センテンスを1件ずつ登録する方法。 |
| 一括登録 | CSV/TSV等のファイルで複数センテンスをまとめて登録する方法。 |
| トレーニング | 自己判断式の学習。バッチ単位でモードをまとめて出題（A通し→同じバッチをB通し）。自動採点はせず、自分で4段階の自己評価をして進める。 |
| モードA（中→意味） | 中国語の**音声を聞いて**、意味を理解できたかを自分で判断するトレーニング。出題時に音声を自動再生し、「🔊 もう一度聞く」で何度でも聞き直せる（テキストは既定で非表示。聞き取れない時のみピンイン/漢字をヒント表示）。答え合わせで中国語（漢字）＋日本語訳を確認する。 |
| モードB（日→中） | 日本語を見て、対応する中国語を書ける（言える）かを確認し自分で判断するトレーニング。回答方式は「頭の中で思い出すだけ」か「テキスト入力」かを設定で切り替えられる。 |
| バッチ・ブロッキング | 1回のトレーニングで、モードごとにまとめて出題する方式（例: 5〜10文をまずA、続けて同じ文をBで）。同じ文をA直後にBで連続させないことで「間隔効果」「望ましい困難」を活かす。既定バッチは5〜10文。 |
| 間隔効果 | 学んだ内容を時間を空けて復習するほうが、続けて詰め込むより記憶に残りやすいという学習の性質。 |
| 望ましい困難（desirable difficulty） | 簡単すぎず少し思い出す努力を要するほうが、記憶が定着しやすいという学習の性質。 |
| 想起（リコール） | 答えを見る前に、自分の頭の中だけで思い出そうとすること。記憶の定着に効果が高い。 |
| 4段階自己評価 | 答え合わせのあとに「もう一度／難しい／できた／簡単」の4つから自分で評価を選ぶこと。この評価をもとに、次にいつ出題するか（間隔反復の間隔）が決まる。 |
| 自己評価良好割合 | 自動採点がないため「正答率」に代わる指標。回答のうち「できた／簡単」と自己評価した割合。 |
| トグル（スイッチ） | トレーニング中に、補助情報（ピンイン＋音声 / 意味 / 重要単語の解説）を表示・非表示で切り替えるスイッチ。ピンインと音声はセットで表示。 |
| 発音トレーニング | センテンスを声に出して読み、その発音を評価する将来機能（いつか実装）。 |

## 間隔反復（記憶の定着のしくみ）に関する用語

| 用語 | 定義 |
|------|------|
| 間隔反復（SRS / Spaced Repetition System） | 忘れるタイミングに合わせて復習の間隔を調整するしくみ。「**忘れた頃にまた同じ問題が出題される**」を実現する、本アプリの中核。 |
| カード（Card） | 「ユーザー × センテンス × モード」ごとの学習状態を表す単位。間隔反復で管理する対象。モードA・Bで別々に持つ。 |
| モード別トラック | 1つのセンテンスについて、モードA・Bそれぞれ別々に持つ間隔反復の進捗（今の状態・次回の出題日）。 |
| SM-2 | 学習アプリ「Anki」などで使われる代表的な間隔反復アルゴリズム（計算手順）。「易しさ係数」で間隔を調整する。**本アプリの最初の版（MVP）で採用**。 |
| FSRS（Free Spaced Repetition Scheduler） | 記憶の確率モデルにもとづく、より新しい間隔反復アルゴリズム。高精度だが複雑。**将来、SM-2から差し替え予定**。 |
| easeFactor（易しさ係数 / EF） | SM-2で、次回までの間隔の伸び率を決める数値（既定2.5・下限1.3）。自己評価が良いほど上がり、間隔が速く伸びる。 |
| new（新規） | まだ一度も学習していないカードの状態。 |
| learning（学習中） | 学習しはじめた直後で、短い間隔で繰り返している状態。 |
| review（復習） | 間隔を空けて復習する、定着フェーズの状態。 |
| lapsed（再学習） | 一度覚えたが忘れてしまい（間違えて）、learning（学習中）に戻った状態。 |
| due（出題期日） | 今日出題すべき状態のカード。いわゆる「忘れた頃」のタイミング。 |

## 中国語に関する用語

| 用語 | 定義 |
|------|------|
| ピンイン（拼音） | 中国語の発音を、ローマ字＋声調記号で表した発音表記。トグルで表示する。 |
| 声調 | 中国語の音の高低のパターン（4声＋軽声）。発音の正誤に関わる。 |
| 簡体字 / 繁体字 | 中国語の字体の種類。本アプリは簡体字を基本とする（繁体字は要検討）。 |
| IME（Input Method Editor / 入力メソッド） | キーボードから中国語（漢字）を入力するための変換ソフト。モードBでテキスト入力する際に使う。 |

## 記録・共有に関する用語

| 用語 | 定義 |
|------|------|
| 記録・統計 | 登録数・自己評価良好割合・日別トレーニング量などの学習履歴をためて、グラフ等で見えるようにすること。 |
| ストリーク（Streak） | 連続して学習した日数。継続のモチベーションの指標。 |
| 共有（Share） | 登録したセンテンス/単語を、他のユーザーに渡す・取り込む機能。 |
| 学習状況シェア | グループ内で、各メンバーの学習量・自己評価良好割合などをお互いに見られる機能。 |
| グループ（Group） | 共有・学習状況シェアのための小規模な集まり（友人・学習仲間・師弟など）。 |

## 技術・開発に関する用語

| 用語 | 定義 |
|------|------|
| Web アプリ | ブラウザ（Chrome・Safari等）で動くアプリ。インストール不要で使える。本アプリはまずこの形で作る。 |
| フロントエンド | 利用者が直接触れる画面側の部分（ボタン・一覧・入力欄など）。 |
| バックエンド | 画面の裏側で、データの保存・認証・同期などを担うサーバー側の部分。 |
| UI（User Interface / ユーザーインターフェース） | 画面の見た目や操作の仕組み。ボタン・メニュー・レイアウトなど、利用者が触れる部分の総称。 |
| PWA（Progressive Web App） | スマホ等にインストールでき、オフラインでも使えるWebアプリの形態。 |
| オフライン | インターネットに接続していない状態。本アプリは接続が切れても基本操作ができることを目指す。 |
| キャッシュ | 一度取得・生成したデータ（音声など）を手元にためておき、次回は素早く再利用するしくみ。通信量やコストを抑える。 |
| API（Application Programming Interface） | ソフト同士が機能やデータをやり取りするための窓口。外部サービス（音声生成など）を呼び出すのに使う。 |
| AI | 人工知能。本アプリではピンインや音声の自動生成などに活用する。 |
| LLM（大規模言語モデル / Large Language Model） | 大量の文章を学習したAI。ChatGPTのような文章生成AI。本アプリではピンイン生成や音声生成に中国系のLLM/APIを利用。 |
| TTS（Text-to-Speech / 音声合成） | 文字（テキスト）から音声を作る技術。センテンスの読み上げ音声の生成に使う。 |
| STT（Speech-to-Text / 音声認識） | 話した音声を文字（テキスト）に変える技術。将来の発音演習の評価に使う。 |
| BaaS（Backend as a Service） | 認証・データベース・保存・権限管理などのバックエンド機能を、まとめて提供してくれるサービス（Supabase・Firebaseなど）。 |
| Supabase（スーパーベース） | 本アプリで採用するオープンソースのBaaS。データベース（PostgreSQL）＋認証＋ファイル保存＋権限管理を提供。クラウド版で開始し、必要ならセルフホスト（自前運用）も可能。 |
| PostgreSQL（ポストグレス） | 広く使われているオープンソースのデータベース（データの保管庫）。Supabaseの中核。 |
| SQL | データベースに対して「条件で絞る・集計する」などの命令を出すための言語。統計の集計などに使う。 |
| Edge Functions（エッジ関数） | Supabase上で動かせる小さなプログラム。外部API（音声生成など）の呼び出しや、秘密の鍵を隠す処理に使う。 |
| Row Level Security（RLS / 行レベルセキュリティ） | データベースの行（1件1件）ごとに「誰が読める・書けるか」を制御するしくみ。共有・グループの権限制御に使う。 |
| IndexedDB（インデックスドDB） | ブラウザに内蔵された保存領域。オフラインでもデータを扱えるよう、手元（端末）にデータをためておくのに使う。 |
| React（リアクト） | 画面（フロントエンド）を作るための代表的なソフトウェア部品（ライブラリ）。Web版の有力候補。 |
| Flutter（フラッター） | 1つのコードでスマホアプリ等を作れる開発の枠組み。将来のモバイル化の候補。 |
| SDK（Software Development Kit） | 開発を助ける道具一式。ここでは Supabase を簡単に使うための部品を指す。 |
| HTTPS | Webの通信を暗号化して安全にやり取りする方式。 |
| OSS（Open Source Software） | ソースコードが公開され、自由に使える/改変できるソフトウェア。特定企業への依存（ロックイン）を避けやすい。 |
| SNS | TwitterやLINEなどの交流サービス。学習状況をシェアする発展形として想定。 |
| CSV / TSV | 表形式のデータをカンマ（CSV）やタブ（TSV）で区切ったテキストファイル。一括登録のテンプレートに使う。 |
| Anki（アンキ） | 間隔反復で有名な暗記アプリ。SM-2アルゴリズムの代表的な採用例として参照。 |
| Sentry（セントリー） | アプリのエラーを記録・通知してくれる監視サービス。運用時の不具合検知に使う想定。 |
| i18n / l10n | 国際化（internationalization）／地域化（localization）の略。UIの言語（日本語）と学習対象の言語（中国語）を分けて扱うこと。 |
| ゲーミフィケーション | バッジ・レベルなどのゲーム的な要素。本プロジェクトでは優先度は低い。 |

## ドキュメントの記号・表記

| 表記 | 意味 |
|------|------|
| MVP（Minimum Viable Product） | 価値を検証するための、最小限の機能をそなえた最初のプロダクト。「まず作る範囲」のこと。 |
| Must / Should / Could | 要件の優先度（MoSCoW法）。**Must＝必須** / **Should＝あるとよい（推奨）** / **Could＝できれば（任意）**。 |
| Phase（フェーズ） | 開発の段階。Phase1（MVP）→Phase2→Phase3… と進む。詳細は [08 ロードマップ](08-ロードマップとMVP.md)。 |
| F-XX | 機能（Function）の通し番号。例: F-01。一覧は [03 機能要件](03-機能要件.md)。 |
| US-XX | ユーザーストーリー（User Story＝利用者視点の要望）の通し番号。例: US-01。一覧は [02 ペルソナとユースケース](02-ペルソナとユースケース.md)。 |
| S-XX | 画面（Screen）の通し番号。例: S-01。一覧は [05 画面・UI要件](05-画面・UI要件.md)。 |
| TBD / 要検討 | まだ決まっていない・今後決める項目を示すマーク（TBD = To Be Determined）。 |
