# 04. 非機能要件

ISO/IEC 25010 の品質特性を参考に整理する。数値は仮置き（`要検討`）。

## 4.1 性能（Performance）

| 項目 | 目標 |
|------|------|
| 画面遷移/センテンス表示 | 体感即時（< 200ms、データ取得後） |
| 音声再生の開始 | タップから < 500ms |
| 一括登録の取り込み | 数百件をプレビュー込みで数秒以内（`要検討`） |
| 同期処理 | バックグラウンドで非同期、UIをブロックしない |

## 4.2 可用性・信頼性（Availability / Reliability）

- 登録したセンテンス・学習記録は消失しない（ローカル保存 + 同期）。
- オフラインでも学習・登録ができ、オンライン復帰時に同期する（`Should`）。
- バックエンドの目標稼働率 99.5% 以上（`要検討`）。

## 4.3 スケーラビリティ

- 個人利用が基本。小規模グループでの共有を想定（〜数十人/グループ）。
- ユーザーごとのセンテンス登録数増加（数千件規模）に耐えること。
- 音声アセット（TTS生成分）のストレージ増加に対応。

## 4.4 セキュリティ・プライバシー

- 通信は全て TLS（HTTPS）。
- パスワードはハッシュ化保存（採用時）。認証トークンは安全に保管。
- **共有・学習状況シェアのプライバシー**を重視:
  - 共有範囲（非公開 / 特定ユーザー / グループ）をユーザーが制御できる。
  - 学習状況の公開粒度（学習量のみ / 正答率含む 等）を選べる（`Should`）。
- 個人情報・学習データの取り扱いを明確化（プライバシーポリシー）。
- 関連法令の遵守: 日本の個人情報保護法ほか（`要検討`）。

## 4.5 ユーザビリティ・アクセシビリティ

- **登録が手早い**こと（個別1件1分以内、一括はテンプレで迷わない）。
- 片手・短時間で学習できるUI。
- 中国語フォント・ピンイン（声調記号）が正しく表示されること。
- 文字サイズ変更、十分なコントラスト、スクリーンリーダー対応を考慮（WCAG 2.1 AA 目標、`Should`）。

## 4.6 保守性・拡張性

- センテンス（コンテンツ）と学習状態（カード/記録）を分離する。
- SRSアルゴリズムを差し替え可能なモジュールとして設計する。
- 学習対象言語の追加が可能なデータ設計（将来の多言語化、[06](06-データモデル.md)）。
- 一括登録の入力形式をバージョン管理し、後方互換を保つ。

## 4.7 互換性・移植性

- Web（PWA）として主要モダンブラウザ（Chrome / Safari / Firefox / Edge）に対応。PC・スマホ両対応。
- 中国語表記は簡体字を基本（繁体字対応は `要検討`）。

## 4.8 運用・監視

- エラー監視・クラッシュレポート（例: Sentry 等）。
- 学習継続率・離脱箇所などの利用解析（プライバシー配慮）。
- ユーザーデータのバックアップ・リストア、エクスポート手段（`Should`）。

## 4.9 コスト・ライセンス

- 音声は TTS 生成を基本（コスト最適化のため**生成結果をキャッシュ/再利用**）。外部API利用は `要検討`。
- 発音評価（STT・声調判定）は従量コスト・精度の観点から段階導入（[08](08-ロードマップとMVP.md)）。
- **共有コンテンツの権利**: ユーザー登録物の共有・再利用に関する規約を定める（`要検討`）。

## 4.10 国際化（i18n / l10n）

- UI言語（日本語）と学習対象言語（中国語）を分離して扱う。
- ピンイン・声調・簡体/繁体など中国語特有の表示差異に対応。
- 将来の学習対象言語追加を見越した設計。
